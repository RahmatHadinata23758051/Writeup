# Writeup - n0t L1c3ns3

## Informasi Challenge

- Judul: `n0t L1c3ns3`
- Kategori: Reverse Engineering
- File: `vmvv(1)`
- Tujuan: recover license key, lalu submit sebagai `THEM?!CTF{license_key}`.

## Ringkasan

Binary yang diberikan adalah PE64 Windows console executable. Program meminta input license, mengecek panjang input harus tepat 17 karakter, lalu menjalankan validator internal yang bentuknya seperti VM kecil/generated bytecode.

String penting yang terlihat dari hasil enumerasi:

```text
Welcome to THEM?!CTF license validator
Bad length. The machine rejects it.
THEM?!CTF{%s}
Nope. The machine keeps laughing.
```

Dari sini terlihat bahwa jika license benar, program akan mencetak:

```text
THEM?!CTF{%s}
```

## Analisis

Panjang license dicek dengan `strlen`, lalu dibandingkan dengan `0x11`, sehingga license key harus sepanjang 17 byte.

Bagian validasi utama berada di sekitar fungsi `0x140002880`. Alur kasarnya:

1. Program membaca input license.
2. Menghapus newline dengan `strcspn`.
3. Memastikan panjang input adalah 17.
4. Untuk setiap karakter, program membangkitkan bytecode kecil dari beberapa tabel di `.rdata`.
5. Bytecode tersebut dieksekusi untuk mengubah state internal dan failure accumulator.
6. Jika semua karakter benar, state akhir harus memenuhi:

```text
fail == 0
checksum == 0x096c4f23
state_byte == 0x53
```

Karena ini PE Windows dan environment utama Linux, validator dieksekusi menggunakan Unicorn Engine. Import seperti `fgets`, `strlen`, `strcspn`, `puts`, dan printf wrapper di-stub agar binary bisa dijalankan secara lokal tanpa Wine.

## Strategi Solving

Alih-alih menulis ulang seluruh VM secara manual, binary dijalankan langsung di Unicorn. Breakpoint penting dipasang pada:

- `0x140002970`: awal proses validasi satu karakter.
- `0x140002be7`: akhir proses satu karakter.

Pada setiap posisi karakter, state emulator disnapshot. Lalu semua kandidat printable dicoba satu per satu. Kandidat yang benar adalah kandidat yang membuat failure accumulator tetap `0` setelah satu karakter selesai diproses.

Hasil recovery per posisi:

```text
0  -> b
1  -> r
2  -> 3
3  -> 3
4  -> 4
5  -> 4
6  -> k
7  -> 1
8  -> n
9  -> g
10 -> t
11 -> h
12 -> 1
13 -> 1
14 -> n
15 -> g
16 -> s
```

License key yang diperoleh:

```text
br3344k1ngth11ngs
```

Saat license ini diberikan ke program, output suksesnya adalah:

```text
THEM?!CTF{br3344k1ngth11ngs}
```

## Flag

```text
THEM?!CTF{br3344k1ngth11ngs}
```
